# SearchForge RAG Demo 演示脚本

本文档用于给汽车保险 broker（南加州华人客户场景）和 HR 展示 SearchForge RAG 系统。

## 📋 Demo 准备

### 前置检查

1. ✅ 后端 API 已部署到 Cloud Run
2. ✅ 前端 Demo 页面可访问（`http://localhost:5173/demo` 或生产环境）
3. ✅ 健康检查端点正常（`/healthz` 和 `/readyz`）
4. ✅ Qdrant Cloud 连接正常，数据已索引

### 演示环境

- **前端 URL**: `http://localhost:5173/demo` (本地) 或生产环境 URL
- **后端 API**: Cloud Run URL（从环境变量 `VITE_API_BASE_URL` 读取）

---

## 🎯 Demo 展示流程

### 第一步：健康检查（30秒）

**操作：**
1. 打开浏览器开发者工具（F12）→ Network 标签
2. 访问健康检查端点：
   ```
   GET {API_BASE_URL}/healthz
   GET {API_BASE_URL}/readyz
   ```

**讲解话术：**
> "首先，我们检查一下系统的健康状态。这是生产环境的标准做法，确保服务正常运行。可以看到 `/healthz` 返回 200 OK，表示服务正在运行。`/readyz` 检查了核心依赖（Qdrant 向量数据库、嵌入模型等）是否就绪。这对于 Kubernetes 自动扩缩容和故障恢复非常重要。"

**预期结果：**
- `/healthz` 返回 `{"ok": true, "status": "healthy"}`
- `/readyz` 返回 `{"ok": true, "clients_ready": true}`

---

### 第二步：Demo 问题 1 - 中文查询（2分钟）

**问题：**
```
加州最低汽车保险要求是什么？
```

**操作：**
1. 在 Demo 页面输入框中输入问题
2. 点击 "Ask" 按钮
3. 等待结果返回（通常 200-500ms）

**讲解话术：**
> "这是一个典型的中文查询场景。我们的系统支持中英文混合查询，这对于南加州的华人客户非常重要。系统会：
> 1. 将中文问题转换为向量表示（embedding）
> 2. 在 Qdrant Cloud 向量数据库中搜索相似文档
> 3. 返回 Top-K 个最相关的结果
> 
> 可以看到，即使查询是中文，系统也能从英文文档中找到相关信息。这是因为我们使用了多语言嵌入模型，能够理解语义相似性，而不仅仅是关键词匹配。
> 
> 每个结果都包含：
> - **Score（相似度分数）**：0-1 之间，越高越相关
> - **Title（标题）**：文档标题
> - **Text（文本片段）**：相关内容的摘要
> - **Source URL（来源链接）**：可以点击查看完整文档"

**预期结果：**
- 返回 5 个相关结果
- Score 在 0.3-0.8 之间
- 结果包含关于 California minimum car insurance requirements 的内容
- 请求延迟 < 500ms

---

### 第三步：Demo 问题 2 - 英文查询（2分钟）

**问题：**
```
How to file a car insurance claim?
```

**操作：**
1. 清空输入框，输入英文问题
2. 点击 "Ask" 按钮
3. 观察结果和延迟

**讲解话术：**
> "这是英文查询。可以看到系统同样能够快速返回相关结果。注意请求延迟显示在页面上，包括：
> - **前端请求延迟**：从浏览器到后端的网络延迟
> - **后端处理延迟**：向量搜索和结果处理的时间
> 
> 我们的系统在 Cloud Run 上运行，具有自动扩缩容能力。在高峰期，系统会自动增加实例数量，保证响应速度。
> 
> 这个查询返回了关于如何提交汽车保险理赔的信息，包括步骤、所需文件等。这对于保险 broker 来说非常实用，可以快速为客户提供准确信息。"

**预期结果：**
- 返回 5 个相关结果
- 结果包含关于 filing insurance claim 的步骤和流程
- 请求延迟 < 500ms

---

### 第四步：Demo 问题 3 - 中英文混合（2分钟）

**问题：**
```
中文用户如何联系保险公司客服？
```

**操作：**
1. 输入中英文混合问题
2. 点击 "Ask" 按钮
3. 展示结果的多样性

**讲解话术：**
> "这是一个中英文混合的查询，这在南加州华人社区很常见。我们的系统能够：
> 1. **跨语言检索**：中文查询可以匹配英文文档
> 2. **语义理解**：不仅仅是关键词匹配，而是理解问题的意图
> 3. **多源整合**：从多个文档中提取相关信息
> 
> 可以看到，系统返回了关于如何联系保险公司客服的信息，包括电话号码、在线聊天、邮件等多种联系方式。这对于保险 broker 来说，可以快速为客户提供准确的客服渠道信息。
> 
> 系统还支持点击 Source URL 查看完整文档，这对于需要详细信息的场景非常有用。"

**预期结果：**
- 返回 5 个相关结果
- 结果包含关于 contacting insurance company customer service 的信息
- 可能包含中文和英文混合的内容

## 📝 Demo 注意事项

1. **网络连接**：确保能访问 Cloud Run 和 Qdrant Cloud
2. **数据准备**：确保 Qdrant 中已有汽车保险相关数据
3. **错误处理**：如果查询失败，检查：
   - 后端 API 是否正常运行
   - 环境变量 `VITE_API_BASE_URL` 是否正确
   - 网络连接是否正常
4. **性能优化**：如果响应慢，可以：
   - 检查 Qdrant Cloud 连接
   - 查看后端日志
   - 检查网络延迟
