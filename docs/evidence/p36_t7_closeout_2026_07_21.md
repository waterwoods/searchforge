## Root cause of `production_like=true`

| Layer | Finding |
|-------|---------|
| Source | Backend Founder QA status (`harness_status` / `console_status`) |
| Mechanism | `production_like` was aliased to `is_production_mode()` |
| Why Cloud QA was wrong | Cloud QA correctly sets `ENV=qa` + `UNIFIED_INTAKE_DB_PRIMARY_WRITES=1`. `is_production_mode()` returns True when DB-primary writes are on — correct for **persistence safety**, incorrect for **operator Production branding** |
| Not the cause | Frontend fallback, hostname guessing, Vercel env (Preview already pointed at Cloud QA after T6) |

Live Cloud QA before fix: `environment=qa` and `production_like=true` simultaneously.

## Fix (smallest safe change)

Added `is_production_deployment()` in `services/fiqa_api/db/service_record_settings.py`:

- `SERVICE_NAME=fiqa-api-qa` or `ENV=qa` → **not** Production branding
- `ENV=prod` or `SERVICE_NAME=fiqa-api` → Production branding
- Missing / ambiguous ENV+SERVICE_NAME → **false** (do not silently claim Production)
- No hostname guessing
- `is_production_mode()` unchanged (data-routing / support-key gates preserved)

Founder QA status now:

| Field | Signal |
|-------|--------|
| `production_like` | `is_production_deployment()` |
| `require_support_key` | `is_production_mode()` (still true on Cloud QA PG-primary) |

Removed `console_status` OR with `is_production_mode()` that re-introduced the defect.
