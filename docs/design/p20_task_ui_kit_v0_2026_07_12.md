## 0. Principles this kit encodes (from the Constitution & benchmarks)

1. **Server-driven, client-rendered** — components render the contract; they never invent phase/next-action/validation.
2. **One primary CTA per page** — enforced by `TaskCTA` (only one `primary` instance per page).
3. **Low typing** — prefer `TaskChoice`/`TaskPhoto`/picker over `TaskField` text.
4. **Every action confirms; every failure recovers** — saving lifecycle + `TaskError` + bounded retry are built into `taskPage`.
5. **Safe to close and resume** — field draft + resume in `taskPage`.
6. **No spinner without text; no unsafe optimistic mutation** — `TaskLoading` always has a message; authoritative state is read back, never faked.
7. **No customer-visible internal jargon** — components only accept customer-safe contract fields (Constitution §3.4 / §6.4).

Each component dir has `index.wxml/.wxss/.ts/.json` (WeChat custom component). Components are **presentational + emit events**; the `taskPage` behavior owns data/loading/errors so components stay reusable across tasks.

## 2. Shared behavior — `taskPage` (build first, A1)

The single most valuable extraction. It retires the per-page duplication documented in the inventory §4 and P20 audit §5.

**Responsibilities:**

| Capability | Behavior |
|-----------|----------|
| `requireToken()` | Read `getApp().taskToken`; if missing → `wx.redirectTo('/pages/entry/entry')`; return token or abort. |
| `loadTask(opts?)` | `CustomerTaskApi.getTask(token)`; set `app.task`; expose `this.data.task` + derived view; on error use **cached `app.task` fallback** + `TaskError`/toast (generalize task-home's current behavior). |
| `withTaskError(fn)` | Wrap async ops: map `ApiRequestError.code` → `mapErrorMessage`; route to `TaskError` (blocking) or toast (retryable) by class. |
| in-flight guard | Central `busy` map (`loading/saving/uploading/submitting/navigating`); components read it; prevents double-tap. |
| saving lifecycle | `saveField(section, fields)` shows immediate "saving", awaits, reads back state, confirms "已保存". Supports **single section-group save** (retires 3-PATCH). |
| upload lifecycle | `uploadEvidence(slot, path)` → optimistic preview → upload → read back `evidence_requirements`. |
| `saveAndReturn()` | Save then `wx.navigateBack()` (replaces `setTimeout(...,400)`). |
| bounded retry | Adopt entry-page pattern: cooldown + `resetApiHealthCache()` + max attempts; expose `retry()`. |
| field draft/resume | Debounced write of in-progress field values to `wx.setStorage` keyed by task+section; restore on `onShow`; clear on successful save. **Fixes story-text-loss (gap G4).** |
| stale-request protection | Tag each load/save with a monotonic seq; ignore responses older than the latest (prevents out-of-order overwrite). |
| analytics hook | `track(event, meta)` → `behaviors/analytics.ts` (no-op stub now). |
| a11y defaults | Provide helpers so components always render text labels + roles. |

**Contract awareness:** when `app.task.task_contract` is present, `taskPage` exposes it as `this.data.contract`; pages/components prefer contract fields, falling back to legacy `taskMapping` inference when absent. This lets A1–A3 ship before Track B emits the contract (A4).

**Outputs:** `this.data.task`, `this.data.contract`, `this.data.busy`, `this.data.error`, and methods above. Pages become: `behaviors: [taskPage]` + a declarative section list + minimal page-specific handlers.

### 2.1 A1 normalization seam (implemented)

- `miniapp/utils/resolveTaskViewModel.ts` is now the single client-side normalization seam.
- Input priority is **contract-first** (`task_contract`) with legacy `taskMapping` inference as migration fallback.
- `taskPage` calls this resolver after task load and cached-fallback paths so all pages can consume a stable `TaskViewModel`.
- Fallback retirement rule is now explicit in code and test evidence: once contract parity passes, client inference stops being authoritative and can be removed.

## 3. Components

Notation: **Native** = WeChat built-in; **Ours** = product component; **TDesign** = deferred (do not add now).

### 3.1 `TaskShell` — Ours
- **Responsibility:** page container (`.container`), scroll region, and the tenant safety footer (`.disclaimer`).
- **Props:** `loading` (bool), `error` (obj|null), `safetyCopy` (string), `showFooter` (bool).
- **Events:** `retry`, `contactBroker` (bubbled from `TaskError`).
- **States:** loading (renders `TaskLoading`), error (renders `TaskError`), content (slot).
- **A11y:** landmark structure; safety copy readable.
- **Contract fields:** `branding.safety_copy`, `error`.
- **First use:** every page wraps its body in `TaskShell`.
- **Page-specific:** the slotted body content.

### 3.2 `TaskHeader` — Ours (thin)
- **Responsibility:** task title + optional instruction line.
- **Props:** `title`, `instruction`.
- **Contract fields:** `title`, `instruction`.
- **First use:** task-home, step pages.

### 3.3 `TaskStatusCard` — Ours
- **Responsibility:** the North-Star hub summary — status pill (label, not color-only), instruction, received list, next-action text.
- **Props:** `status` (customer-safe label), `statusTone` ("active"|"done"), `instruction`, `received` (string[]), `nextActionText`.
- **Events:** none (CTA is separate).
- **States:** collecting / review_ready / submitted / broker_follow_up / expired → distinct labels.
- **A11y:** status conveyed by **text**, not color alone.
- **Contract fields:** `task_status`, `instruction`, derived received from `sections`/`fields`, `next_action.label`.
- **First use:** task-home.
- **Page-specific:** none.

### 3.4 `TaskProgress` — Ours
- **Responsibility:** show `completed/total` as **text + bar** (fixes gap G9).
- **Props:** `completed` (number), `total` (number).
- **Contract fields:** `progress.completed`, `progress.total`.
- **A11y:** renders "3 / 6" text; bar is decorative with `aria`-equivalent text.
- **First use:** task-home (and step pages optionally).

### 3.5 `TaskSection` — Ours (thin)
- **Responsibility:** labeled group wrapper (`.section-label` + `.section-gap`) hosting one field/choice/photo group.
- **Props:** `label`, `status` ("received"|"needed"|"optional").
- **Contract fields:** `sections[].label`, `sections[].status`.
- **First use:** basics, story, photos.

### 3.6 `TaskField` — Ours
- **Responsibility:** one labeled input: text / textarea / **date / datetime (native picker)** / number, with inline validation + draft.
- **Props:** `key`, `label`, `componentType` ("text"|"long_text"|"date"|"datetime"|"number"), `value`, `placeholder`, `required`, `validation` (min length etc.), `maxLen`.
- **Events:** `change({key,value})`, `blur` (triggers draft save).
- **States:** empty / editing / valid / invalid(with message) / disabled(in-flight).
- **A11y:** **persistent visible label** (never placeholder-only); error text announced.
- **Contract fields:** `sections[]` of `component_type` `long_text`/`text`/`date`/`datetime`, `validation`, `fields[key]`.
- **First use:** story (long_text), basics (datetime picker for `accident_datetime`, text for location/vehicle). **This introduces the native date picker that fixes gap G2.**
- **Page-specific:** which fields a page shows (from contract or legacy list).

### 3.7 `TaskChoice` — Ours
- **Responsibility:** single-select chips from contract `choices`; single tap selects (and may advance).
- **Props:** `key`, `label`, `choices` ([{value,label}]), `value`.
- **Events:** `select({key,value})`.
- **States:** unselected / selected(active) / disabled.
- **A11y:** each chip is a button with selected state in text/role, not color-only.
- **Contract fields:** `sections[]` of `component_type: choice`, `choices`, `fields[key]`.
- **First use:** basics (injury). Reuses `.radio-chip`.

### 3.8 `TaskPhoto` — Ours
- **Responsibility:** slot-identity photo capture/upload/retry (replaces count-based logic; fixes gap G7 client side).
- **Props:** `slots` ([{slot,label,received,localPath?}]), `uploadUrl`, `busy`.
- **Events:** `add({slot})`, `retry({slot})`, `preview({slot})`, `done`.
- **States per slot:** empty / picked(local preview) / uploading / uploaded / error(retry).
- **A11y:** each slot has label + state text; tap targets ≥ 88rpx; retry is a clear button.
- **Contract fields:** `evidence_requirements` ([{slot,label,min,received}]).
- **First use:** photos. Uses `mediaCaptureAdapter.choosePhoto`.
- **Page-specific:** none (slots come from contract; fallback to current `SLOT_SEQUENCE`).
- **Backend dependency:** content-hash dedup (R11) is a Track B fix; kit tolerates it (idempotent re-upload).

### 3.9 `TaskMissingList` — Ours
- **Responsibility:** "received ✓ / still-needed ○" rows with per-row status + tap-to-navigate (the current task-home supplement rows).
- **Props:** `rows` ([{key,label,statusText,actionable,route,hint}]).
- **Events:** `tapRow({key,route})`.
- **States:** actionable(arrow) / static(hint) / completed(hidden).
- **A11y:** row status in text; actionable rows are buttons.
- **Contract fields:** `missing_items`, `sections[].status`, `evidence_requirements`.
- **First use:** task-home. Sourced from `buildSupplementRows` today; contract-driven later.

### 3.10 `TaskCTA` — Ours
- **Responsibility:** the single primary action; embeds in-flight guard (disabled + loading) and single-CTA rule.
- **Props:** `label`, `disabled`, `loading`, `reason` (why-disabled text, optional).
- **Events:** `tap` (suppressed while loading/disabled).
- **States:** enabled / disabled(with reason) / loading.
- **A11y:** button; disabled reason readable; ≥ 96rpx height (existing `.btn-primary`).
- **Contract fields:** `next_action.label`, `submit_ready`/`review_ready` (to enable/disable).
- **First use:** every page footer (`.footer-cta`).
- **Rule:** at most one `TaskCTA` per page.

### 3.11 `TaskSecondaryAction` — Ours (thin)
- **Responsibility:** demoted secondary action (`.btn-secondary`) — "稍后再填", "查看全部资料".
- **Props:** `label`, `disabled`.
- **Events:** `tap`.
- **First use:** step pages, task-home.

### 3.12 `TaskLoading` — Ours
- **Responsibility:** full-region loading with **required explanatory message** (no bare spinner).
- **Props:** `message` (required).
- **First use:** entry, task-home, photos (via `TaskShell`).

### 3.13 `TaskError` — Ours
- **Responsibility:** unified inline error (fixes gap G6): safe message + bounded **retry** + **联系陈总**. Replaces the fragmented page/card/toast split for blocking errors.
- **Props:** `code`, `message`, `canRetry`, `retryDisabled` (cooldown).
- **Events:** `retry`, `contactBroker`.
- **States:** retryable / blocking(no retry, contact only).
- **A11y:** message + actions as buttons.
- **Contract fields:** `error.code`, `error.message` (customer-safe envelope).
- **First use:** entry, task-home, photos, receipt (via `TaskShell`). Standalone `pages/error` becomes a thin host of `TaskError`.

### 3.14 `TaskReview` — Ours
- **Responsibility:** read-only pre-submit summary (story, basics, photo count, received/missing) + edit links; **does not** re-derive submit readiness (reads `submit_ready`).
- **Props:** `story`, `fields`, `photoCount`, `received`, `missing`, `submitReady`, `disclaimer`.
- **Events:** `edit({target})`, `submit`.
- **States:** submit-ready / not-ready(disabled CTA + reason).
- **Contract fields:** `fields`, `sections`, `evidence_requirements`, `submit_ready`, `branding.safety_copy`.
- **First use:** review. Submit uses `submit_intent_id` idempotency (existing).

### 3.15 `TaskReceipt` — Ours
- **Responsibility:** post-submit confirmation + status + next step + supplement CTA (+ submitted timestamp when available, gap G10).
- **Props:** `title`, `message`, `status`, `photoCount`, `nextStep`, `disclaimer`, `submittedAt?`.
- **Events:** `viewStatus`, `supplement`.
- **Contract fields:** `task_status: submitted`, `timestamps.updated_at`, `branding.safety_copy`, completion summary.
- **First use:** receipt.

## 5. What stays page-specific (do NOT componentize)

- **Page composition** — which sections/components a given task page shows and in what order.
- **Launch/routing orchestration** — `entry` remains a controller page.
- **Task-unique copy** the contract can't yet express.
- **Navigation topology** — the hub-and-spoke page stack (task-home ↔ steps) stays as pages; the kit does not impose a router.

---

## 6. Non-goals (guardrails)

- **No generic form/schema engine.** `TaskField`/`TaskChoice` support a **fixed, small set** of `component_type`s proven by Claim; new types are a deliberate addition, possibly needing a release (Constitution §6.5).
- **No TDesign dependency added now** (see benchmark/audit §9).
- **No framework** (Taro/React/Vue/uni-app) — WeChat custom components only.
- **No client-authoritative workflow** — components render server truth; legacy inference is fallback only, slated for removal once the contract is emitted.
