# Standard Scenario Package Definition Spec

**Purpose:** Define the package clearly: name, target users, included scenarios, office support, in-scope vs deferred.

**Scope:** Chen Kui Insurance Unified Entry — Sellable Standard Scenario Package

---

## 1. Package Name

**Chen Kui Broker Standard Package** (or **Broker Standard Package** for reuse)

- **Short:** "Broker Standard Package"
- **Full:** "Unified Intake + Broker Workbench — Standard Scenario Package for Small Auto Insurance Brokers"

---

## 2. Target Users

| User | Profile |
|-----|---------|
| **Primary** | California auto insurance brokers serving Chinese-speaking clients (e.g., Chen Kui) |
| **Secondary** | Small brokers / small merchants with similar intake patterns |
| **Office size** | 1–5 people; manual triage; WeChat/email as primary channels |

---

## 3. Business Value

| Stakeholder | Value |
|-------------|-------|
| **Broker** | Less manual triage; fewer repetitive explanations; clearer next steps; no lost follow-ups |
| **Merchant / client** | Faster broker response; clearer what to send; less back-and-forth |
| **Office** | One structured case per message; one next move; one draft to edit |

---

## 4. Included Scenario Set

| # | Scenario | Business goal | Commercial importance |
|---|----------|---------------|------------------------|
| 1 | **Quote / Add-car** | New vehicle quote; add car to policy | Revenue; high-frequency |
| 2 | **Policy change (add/remove)** | Add/remove vehicle; coverage change | Operational; routine |
| 3 | **Material collection / already sent** | Missing document; client says already sent | Operational; common pain |
| 4 | **Renewal increase / premium review** | Premium too high; renewal notice | Retention; high-frequency |
| 5 | **Billing clarification** | Payment failed; cancellation risk; payment proof | Urgency; same-day action |
| 6 | **Claim first notice** | Accident; hit-and-run; first-response guidance | Operational; time-sensitive |
| 7 | **Talk to Agent / case handoff** | Customer wants human; broker takes over | Trust; clarity |

---

## 5. Office-Side Support

| What office gets | From package |
|------------------|--------------|
| **Case focus** | Add car quote · Premium review · Claim intake · Missing document · Payment risk |
| **Your next move** | One operational sentence per case |
| **Collected** | Green chips: what customer already provided |
| **Still needed** | Orange chips: what broker should ask or verify |
| **Client reply draft** | Editable; broker confirms before sending |
| **Queue triage** | Work now / Waiting or parked; urgency; readiness |

---

## 6. What a Broker Gets

- One paste → structured case
- One next move per case
- One draft to edit (not write from scratch)
- Lightweight follow-up memory (waiting on, next contact)
- No auto-send; broker stays in control

---

## 7. What a Merchant / Client Gets

- Faster broker response
- Clearer what to send
- Less back-and-forth
- Same broker relationship; no automation surprise

---

## 8. In Scope vs Deferred

| In scope | Deferred |
|----------|----------|
| 7 core scenarios above | Email/WeChat/SMS integration |
| Inbox triage (paste) | OCR upload |
| Multi-turn collection (2–3 turns) | Full CRM |
| Case handoff + workbench | Multi-tenant |
| Founder demo queue | Stripe billing |
| Simulation Assistant | Carrier API integration |
