# ADD-CAR INDUSTRIAL SCORECARD V1 — Blueprint

## Sprint goal

Establish a **fixed, reusable scorecard** (PAGE / FLOW / STATE / HANDOFF) to judge how industrialized the **Add-Car flagship path** is today, map gaps honestly, and recommend the **highest-value next sprint**—without redesigning the product in this sprint.

## Why now

Multiple Add-Car sprints improved portal copy, flow track, result card, workbench echo, and rule-path realism. Without a shared scorecard, progress is easy to judge by mood or a single visible tweak. The founder needs a **stable decision framework** aligned with `docs/PROJECT_TRUTH_SWITCH.md` (Add-Car-first, pilot-safe operations, clarity over breadth).

## Scope

- Define scorecard criteria and 1–5 scale.
- Assess current Add-Car using repo evidence: `UnifiedIntakePage.tsx`, `clientConfig.ts` defaults, recent sprint final reports, simulation audit outcomes.
- Score PAGE / FLOW / STATE / HANDOFF; list top blockers and next sprint options.

## Non-scope

- Broad UI redesign, backend rewrites, new features, large doc sets, deployment work, non–Add-Car prioritization.

## Current decision problem

“We know Add-Car got better, but **how pilot-credible is it end-to-end**, which layer is the bottleneck, and **what one sprint moves the commercial needle**?”

## Target outcome

- Three short docs in this folder (blueprint, scorecard, final report).
- Founder-readable scores, gap map, and a clear **recommended next sprint** with rationale.
