# Workbench Demo UX Bugfix Blueprint

**Sprint:** Workbench Demo UX + Visual Bug Fix Sprint  
**Created:** 2026-03-19  
**Scope:** SearchForge → Chen Kui Insurance Unified Entry

---

## 1. Why This Sprint Matters Now

The product is close to real broker trial readiness. At this stage, obvious frontend/demo bugs are especially harmful because they damage:
- trust
- product feel
- founder confidence
- broker confidence
- trial readiness

A broken demo queue button or unreadable visual area creates the impression of an unfinished MVP even if the backend logic is strong.

---

## 2. Why These Are Fix-Now Issues

| Issue | Impact | Fix-now reason |
|-------|--------|----------------|
| "加载演示队列" unclear behavior | Founder cannot tell if load succeeded or failed | Core demo path; first broker action |
| Lower cards unreadable | Broken-MVP feel; broker cannot scan cases | Above-the-fold workbench; daily use |
| No visible feedback during/after load | Founder guesses; loses confidence | Trust signal; trial readiness |

---

## 3. What This Sprint Will Strengthen

1. **Queue load clarity** — Founder knows: loading started, succeeded, failed, or already ready
2. **Readable cards** — Lower demo/workbench cards readable without highlighting text
3. **Stronger contrast** — Tags, labels, text, backgrounds meet basic readability
4. **Stable demo path** — Workbench feels less broken during demo/trial use

---

## 4. What This Sprint Intentionally Will NOT Do

- Redesign the entire UI
- Add broad new features
- Expand into unrelated product work
- Pixel-perfect polish
- Change backend triage logic
- Modify Simulation Assistant

---

## 5. Success Definition

At the end of this sprint:
- Founder can click "加载演示队列" and understand what happened
- Founder can read the lower demo cards without highlighting text
- Workbench feels more stable and trustworthy during demo/trial use
