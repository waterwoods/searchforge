# Product / Package 2.0 Blueprint

**Sprint:** Standard Scenario Package 2.0  
**Scope:** SearchForge → Chen Kui Insurance Unified Entry  
**Created:** 2026-03-18

---

## 1. Why Package 2.0 Matters Now

The current Standard Scenario Package (7 scenarios) is sellable and demo-ready. The founder has:
- customer entry, multi-turn continuity, workflow_state, case creation, broker workbench
- a standard scenario package and real broker trial package
- stronger later-turn behavior (follow_up_type, clarification-first, already_sent)

**The gap:** The strongest commercial chains are "included" but not yet **deep enough**. For a paid pilot or trial, the broker needs:
- fewer manual follow-up questions after handoff
- more useful summaries and next-step guidance
- more natural later-turn handling
- clearer "what the office gets" at handoff

Package 2.0 is the next step: **deepen the top 3–5 commercial flows** so the package becomes more convincing, more reusable, and more valuable for a small broker trial.

---

## 2. Why This Is the Right Move After the Current Package

| Before Package 2.0 | After Package 2.0 |
|--------------------|-------------------|
| Scenarios included | Scenarios **deepened** |
| First-turn strong | **Full chain** strong (recognition → later turns → handoff → summary → office) |
| Handoff exists | Handoff **more useful** to broker |
| Workbench shows chips | Chips **more accurate** (collected / still needed) |
| "Good enough" for demo | **Pilot-ready** for real broker use |

---

## 3. What This Sprint Will Strengthen

1. **Add-car / quote** — Later-turn field collection order, handoff summary, broker_next_step clarity
2. **Material collection / already sent** — "Client says sent" handling, summary usefulness, broker verification guidance
3. **Renewal premium / premium review** — Policy/bill collection, handoff when client sends bill
4. **Payment / cancellation risk** — Urgency clarity, "already paid" handling, broker_next_step
5. **Talk to Agent / case handoff** — Mid-flow detection, handoff timing

---

## 4. What This Sprint Intentionally Will NOT Do

- Add new scenarios beyond the 7
- Add platform features (Stripe, multi-tenant, CRM)
- Improve docs without improving product behavior
- Spread effort across all 7 scenarios equally
- Add random features

---

## 5. Success Definition

At the end of this sprint:
- The top 3–5 commercial flows are **noticeably deeper**
- Broker would likely ask **fewer manual follow-up questions**
- Package feels **more credible to sell or trial**
- Package is **easier to explain and reuse**
