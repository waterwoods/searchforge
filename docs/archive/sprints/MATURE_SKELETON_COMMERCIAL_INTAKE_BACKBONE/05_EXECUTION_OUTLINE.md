# Execution Outline

**Sprint:** Mature Skeleton / Commercial Intake Backbone Sprint  
**Purpose:** Workstreams, loop plan, synthesis process, how future teams should use the backbone.

---

## 1. Workstreams

| Workstream | Owner | Output |
|------------|-------|--------|
| **Baseline audit** | Product strategist | Strongest assets, biggest gaps, likely mistake without backbone |
| **Reference pattern analysis** | Mature product pattern analyst | Borrow map; what to copy/adapt/skip per reference |
| **Backbone synthesis** | Customer intake flow analyst + Broker handoff analyst | Page, flow, state, handoff specs |
| **Challenge & refine** | Reviewer / skeptic | Fit for small CA broker, Chinese-speaking, lightweight commercial SaaS |
| **Final backbone editor** | Final editor | Mainline document; founder notes; 10–20 point breakdown |

---

## 2. Loop Plan

### Loop 1 — Reference Pattern Analysis

- Analyze Stripe, Amazon-style, Intercom/Shopify Inbox, Zendesk
- Produce first borrow map
- Output: Reference Pattern Analysis Spec; first comparison table

### Loop 2 — Backbone Synthesis

- Define page, flow, state, handoff backbones
- Challenge: Does it fit small CA broker, Chinese-speaking, lightweight commercial?
- Output: Page/Flow/State/Handoff Backbone Spec; adaptations documented

### Loop 3 — Finalize Mainline Guidance

- Make founder-usable
- Make future-sprint-usable
- Tradeoffs explicit; next vs later defined
- Output: Founder Mainline Notes; Acceptance Criteria; final report

---

## 3. Synthesis Process

1. **Extract** — From each reference: what is structurally strong for our use case
2. **Compare** — Side-by-side: page, flow, state, handoff
3. **Synthesize** — One backbone per dimension; no single-product copy
4. **Challenge** — Does it fit Chen Kui? Chinese-speaking? Lightweight? Paid-product feel?
5. **Refine** — Adjust for vertical insurance; document tradeoffs

---

## 4. How Future Teams Should Use the Backbone

| When | Use |
|------|-----|
| **Starting a UI sprint** | Check Page Backbone; align hero, primary actions, free input |
| **Starting a flow sprint** | Check Flow Backbone; align entry → triage → collect → handoff → follow-up |
| **Adding state** | Check State Backbone; use need_more, almost_ready, quote_ready, etc. consistently |
| **Changing handoff** | Check Handoff Backbone; case focus, next move, collected, still needed, correction/already_sent |
| **Evaluating a feature** | Check Borrow-vs-Build; is it borrow, adapt, vertical-specific, or defer? |
| **Scope creep** | Check Defer list; push back on real-time chat, multi-channel, full ticketing, etc. |
