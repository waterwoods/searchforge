# Product Value Review Blueprint

**Sprint:** Product Value Review Sprint  
**Scope:** SearchForge → Chen Kui Insurance Unified Entry  
**Created:** 2026-03-19

---

## 1. Why Value-Based Prioritization Matters Now

The product has evolved through demo → sellable package → scenario hardening → Real Broker Trial Package. Multiple development directions are now active:

- Add-Car Quick Intake Card
- Attachment upload (visible in case)
- OCR / AI-assisted extraction
- Workbench handoff strengthening
- Mixed-intent broker action clarity
- Configuration/template expansion
- Further scenario hardening
- Trial execution improvements

**Without disciplined prioritization**, the team risks:
- Spending days on features that add 2/10 value when another could add 8/10
- Choosing by intuition instead of commercial leverage
- Rewarding technical novelty over business value
- Optimizing for "interesting" instead of real broker trial and paid adoption

**Value-based prioritization** gives the founder a clear answer to:
- What should we do next?
- What is high-value now?
- What should wait?
- What is attractive but low ROI?

---

## 2. Why This Is the Right Move at the Current Product Stage

| Stage | Status |
|-------|--------|
| Demo | ✓ Done |
| Sellable package | ✓ 7 scenarios, workbench part of package |
| Scenario hardening | ✓ Add-car excellence, mixed-intent, handoff timing |
| Trial package | ✓ Documented; kickoff-ready |
| **Real broker trial** | **Not yet executed** |

The product is **trial-ready** but the **first real broker trial has not run**. The next step is either:
- **A:** Run the trial and learn from real usage
- **B:** Add one more high-leverage feature before trial
- **C:** Defer trial and build something expensive (trap)

This sprint decides which of A or B is correct, and what to avoid (C).

---

## 3. What This Sprint Will Strengthen

1. **Prioritization discipline** — Clear scoring model; no silent ranking
2. **Commercial lens** — Trial adoption, broker usefulness, future paid adoption
3. **Explicit tradeoffs** — What we intentionally exclude and why
4. **Single recommendation** — One best next sprint, not five equal options
5. **Reusable framework** — Founder can reuse before future sprints

---

## 4. What This Sprint Will NOT Do

- Build any new feature
- Change code or config
- Expand scope beyond prioritization
- Treat all ideas as equal
- Reward technical novelty over business value

---

## 5. Success Definition

At the end of this sprint:
- Ranked list of most important next product directions
- Clear value-scoring method
- Explicit "do now / do next / defer" buckets
- One recommended next sprint
- Founder-friendly prioritization framework for future use
