# TRUTH-LAYER ENFORCEMENT + GAP CHECK — Blueprint

## Sprint goal

Use `02_TWO_LAYER_STANDARD_SPEC.md` as a checklist against the live Add-Car path, document compliance gaps, and ship the smallest high-trust enforcement moves (reply + UI truth gates)—without redesigning the product.

## Why now

The two-layer industrial standard is published; the system must move from “standard written” to “standard enforced” on the flagship wedge so demos and pilots do not claim office receipt or queue placement before formal submit truth exists.

## Read-first docs

1. `docs/UNIFIED_INTAKE_PRODUCT_AND_TECHNICAL_MASTER_OUTLINE.md`
2. `docs/PROJECT_TRUTH_SWITCH.md`
3. `docs/sprints/TRUTH_LAYER_REPLY_LAYER_INDUSTRIAL_STANDARD_SPRINT/02_TWO_LAYER_STANDARD_SPEC.md`

## Scope

- Add-Car only: truth vs reply alignment, formal-submit vs `handoff_ready` / `handoff_pending`.
- Client handoff/stitched copy, `triage.py` fallbacks, right-rail formal-complete helper.

## Non-scope

- CRM / workflow engine, broad refactors, non–Add-Car lanes, large doc sets.

## Target outcome

- Fewer customer-visible lines that imply office receipt or office queue before formal office-visible persistence.
- Right-rail “step 3 / office has it” only when structured time/lifecycle truth supports it.
- Written gap record + recommended next sprint.
