# State / Workflow Backbone Phase 2 — Conversation / Session Continuity Spec

**Purpose**: Define conversation/session identity before and after case creation.

---

## 1. What Is a Conversation/Session Before Case Creation?

- **Session**: A logical thread of customer + system turns in Customer Entry, before handoff.
- **Identity**: `session_id` (UUID) generated by frontend on first message.
- **Persistence**: session_id stored in localStorage; passed with each triage request.
- **Scope**: Same browser tab; same Customer Entry flow.

---

## 2. When Is conversation_id / session_id Created?

| Event | Action |
|-------|--------|
| First message in Customer Entry | Frontend generates `session_id` (UUID); stores in localStorage |
| Each triage request | Frontend sends `session_id` in request body (optional) |
| Handoff + persist | Case created; `case_id` becomes canonical identity |
| New conversation | User clicks "New" or starts fresh; new session_id generated |

---

## 3. Relationship Between conversation_id and case_id

| State | Identity | Notes |
|-------|----------|-------|
| **Before handoff** | session_id (conversation_id) | UI-only; not persisted server-side |
| **After handoff** | case_id | case_id = canonical; case_messages = conversation |
| **Append** | case_id | case_id identifies thread; no session_id needed |

**Rule**: No separate conversation_id in storage. Case = conversation once persisted. Pre-persist, session_id is client-side only.

---

## 4. First-Turn / Follow-Up / Append Semantics

| Path | Entry | session_id | case_id |
|------|-------|------------|---------|
| First turn | triage_conversation(text, []) | Optional from client | None |
| Follow-up | triage_conversation(text, turns) | Same session_id | None until handoff |
| Handoff | persist_case=true, handoff_ready=true | — | Created |
| Append | triage_for_append + append_follow_up_message | Not used | Required |

---

## 5. What Happens When User Continues Same Topic vs Starts New One?

- **Same topic**: Same session_id; turns accumulate in React state; triage receives conversation_turns.
- **New topic**: User clicks "New" or equivalent; new session_id; turns reset.
- **Refresh mid-conversation**: session_id in localStorage; turns in React state are lost unless we persist them (Phase 2: we do NOT persist turns server-side; optional future: persist turns in localStorage keyed by session_id).

---

## 6. API Contract

### Request (POST /api/inbox/triage)
```json
{
  "text": "...",
  "persist_case": false,
  "conversation_turns": [...],
  "session_id": "uuid-optional"
}
```

### Response (when no case persisted)
```json
{
  "handoff_ready": false,
  "conversation_id": "uuid-from-request-or-generated",
  ...
}
```

- `conversation_id`: Echo of session_id when provided; otherwise omit or generate for debugging.
- When case persisted: response includes `case_id`; `conversation_id` not needed.
