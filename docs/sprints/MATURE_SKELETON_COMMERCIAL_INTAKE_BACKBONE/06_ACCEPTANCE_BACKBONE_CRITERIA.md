# Acceptance / Backbone Criteria

**Sprint:** Mature Skeleton / Commercial Intake Backbone Sprint  
**Purpose:** Practical criteria for clarity, usefulness, realism, commercial relevance, reusability.

---

## 1. Clarity Criteria

| Criterion | Pass When |
|-----------|-----------|
| **Page backbone** | Hero, primary action, free input, supporting areas explicitly defined; no ambiguity |
| **Flow backbone** | Entry → triage → collect → confirm → handoff → follow-up; each stage has clear definition |
| **State backbone** | need_more, almost_ready, quote_ready, escalation, etc. listed with meaning and use |
| **Handoff backbone** | Case focus, next move, collected, still needed, urgency, correction/already_sent defined |
| **Borrow map** | Each reference (Stripe, Amazon, Intercom, Zendesk) has borrow/adapt/skip clearly stated |

---

## 2. Usefulness Criteria

| Criterion | Pass When |
|-----------|-----------|
| **Founder-usable** | Andy can read and apply in 10 minutes; no jargon overload |
| **Sprint-usable** | Future UI/flow/state sprints can check alignment without re-reading everything |
| **Decision-enabling** | Borrow-vs-Build answers "should we copy X?" for common cases |
| **Guardrail** | Explicit "do not copy" and "defer" lists prevent scope creep |

---

## 3. Realism Criteria

| Criterion | Pass When |
|-----------|-----------|
| **Fits small broker** | Backbone assumes 1–5 person office; no enterprise workflows |
| **Fits Chinese-speaking** | Tone, handoff phrases, entry points support 华语客户 |
| **Fits paste-based** | No assumption of real-time chat, email sync, or WeChat integration |
| **Fits pilot scope** | Single broker; manual payment; no multi-tenant |

---

## 4. Commercial Relevance Criteria

| Criterion | Pass When |
|-----------|-----------|
| **Trust** | Page backbone optimizes for trust/hero above fold |
| **Clarity** | Flow and handoff reduce broker rework; one next move per case |
| **Paid-product feel** | Structure supports "this is worth paying for" not "this is a demo" |
| **Vertical specialization** | Add-car, quote-ready, cancellation, missing doc are first-class |

---

## 5. Reusability Criteria

| Criterion | Pass When |
|-----------|-----------|
| **Stable reference** | Backbone does not change every sprint; only refined with explicit rationale |
| **10–20 point breakdown** | Concrete points listed; no vague "improve UX" |
| **Future-sprint alignment** | Document states how future sprints should align |
| **Defer list** | Clear what is intentionally not in scope |

---

## 6. Pass/Fail Summary

**Pass:** All 5 categories (clarity, usefulness, realism, commercial relevance, reusability) have criteria met.

**Fail:** Any category has ambiguous or missing criteria.
