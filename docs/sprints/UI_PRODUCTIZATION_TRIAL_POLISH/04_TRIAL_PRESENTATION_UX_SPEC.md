# Trial Presentation UX Spec

**Purpose:** Define what the founder most needs to show in a live demo and what should feel polished.

---

## 1. Demo Path (from STANDARD_SCENARIO_PACKAGE)

1. Load founder demo queue
2. Cancellation risk (opens first)
3. Reopen missing document from Recent cases
4. Reopen add-car quote or premium review
5. Optional: Simulation Assistant

---

## 2. Screens That Must Leave the Best Impression

| Screen | What matters |
|--------|--------------|
| **Customer Entry** | Welcome area, quick-start buttons, clarity of "what can I do here" |
| **Workbench queue** | Case cards readable, "Action now" / "Your move" visible |
| **Current case** | "Your next move" prominent, collected/still needed clear, draft visible |
| **Handoff ready** | Success message, "查看工作台" button |

---

## 3. UX Weaknesses That Most Hurt Trust

- **Internal labels:** "Unified Intake", "Founder demo snapshot", "Local/demo-safe"
- **Debug-like:** "Case ID", "lifecycle_status", raw status codes
- **Cluttered:** Too many tags, no visual hierarchy
- **Unclear primary action:** User doesn't know what to do first
- **Mixed language:** Inconsistent English/Chinese in same flow

---

## 4. What Should Feel Polished in Demo

- **Entry:** Clear welcome, obvious buttons, trust reassurance.
- **Workbench:** Load queue → one click, case opens → next move visible.
- **Case card:** Focus, attention, preview — readable at a glance.
- **Copy actions:** "Copy client draft", "Copy case snapshot" — obvious and usable.

---

## 5. What the Founder Should Say

- "This is the Broker Standard Package. One paste → structured case. One next move. One draft to edit. The workbench is part of the package. No auto-send."

---

*End of Trial Presentation UX Spec*
