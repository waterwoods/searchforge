# Acceptance / UI Productization Criteria

**Purpose:** Practical criteria for "done" and "acceptable to defer."

---

## 1. Clearer Entry

- [ ] Welcome message is clear and reassuring
- [ ] Quick-start buttons are prominent and understandable
- [ ] Trust copy ("消息会直接转给办公室") is visible
- [ ] Primary action (Submit/Send) is obvious
- [ ] No internal labels in customer-facing text

---

## 2. Stronger Workbench Readability

- [ ] "Your next move" is prominent and readable
- [ ] Case cards show focus, attention, preview — readable at a glance
- [ ] Collected / Still needed are grouped and clear
- [ ] Section names are product-like, not internal

---

## 3. Stronger Action Visibility

- [ ] Primary actions (Load queue, Start case, Reopen case) are obvious
- [ ] Copy actions (Copy draft, Copy snapshot) are visible

---

## 4. Stronger Demo Confidence

- [ ] Founder demo path (Load queue → Cancellation risk) works and looks polished
- [ ] No "debug" or "internal" labels visible

---

## 5. Lower MVP/Debug Feel

- [ ] "Founder demo snapshot" — renamed or collapsible
- [ ] "Local/demo-safe" — removed or hidden
- [ ] "Unified Intake" — not in customer-facing header

---

## 6. Acceptable to Defer

- Full rebranding
- Custom animations
- Theme system overhaul
- Pixel-perfect design
- Mobile layout optimization

---

*End of Acceptance Criteria*
