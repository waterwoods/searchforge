# ADD-CAR BROKER-FIRST STATE + FLOW HARDENING — Blueprint

## Sprint goal

Harden **Add-Car only** so a broker’s **first impression** is: one business task, one service record, one scannable state, clear next-step ownership, and continuity between customer view, result card, and office workbench—**without** redesigning the page or rewriting the engine.

## Why now

- PAGE and HANDOFF are already strong; scorecard (**FLOW 3**, **STATE 3**) still flags **conversation-first gravity** and **record/state scan order**.
- This sprint applies **minimal ordering and typography** so state and record ID lead the eye before thread noise and queue tags.

## Read-first docs

1. `docs/UNIFIED_INTAKE_PRODUCT_AND_TECHNICAL_MASTER_OUTLINE.md` — flagship Add-Car, state-driven flow, record-first.
2. `docs/PROJECT_TRUTH_SWITCH.md` — safe edit zones, canonical path.
3. `docs/sprints/ADD_CAR_INDUSTRIAL_SCORECARD_V1_SPRINT/02_ADD_CAR_INDUSTRIAL_SCORECARD_V1.md` — baseline scores and gaps.
4. `docs/sprints/ADD_CAR_INDUSTRIAL_SCORECARD_V1_SPRINT/03_FINAL_REPORT.md` — recommended follow-ups (flow vs chat, workbench parity).

## Scope / non-scope

**In scope:** Add-Car state prominence, next-step scan order, record ID alignment customer ↔ workbench, light copy default for result-card hint, lightweight validation.

**Out of scope:** Non–Add-Car flows, backend/triage changes, broad UI polish, CRM, deployment, large doc sets.

## Target outcome

After this sprint, on Add-Car:

- Pre-handoff **progress/state card appears above** the message thread.
- Post-handoff **服务记录编号** sits **immediately under** the status strip on the result card.
- Workbench **queue cards** show **status strip → record ID →** tags (Add-Car), matching customer mental model.
