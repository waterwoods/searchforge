# Unified Intake UI Professionalization Blueprint

**Sprint**: Unified Intake UI Professionalization  
**Date**: 2026-03-20  
**Budget**: 30–60 minutes  
**Scope**: Customer-facing intake page productization — no new backend features

---

## 1. Why the Current Page Still Feels Like a Demo / Internal Tool

- **URL**: `/workbench/unified-intake` — "workbench" signals internal tool
- **Visual language**: Dark-theme remnants (rgba(255,255,255,...)) on light background; fragmented card styling
- **Structure**: One big textarea dominates; quick-start buttons feel like scattered chips
- **Trust**: Thin hero; no explicit "office will follow up" framing above the fold
- **Hierarchy**: "客户入口" + "模拟演示" compete; primary path unclear
- **Identity**: Feels like a subpage of a lab, not a standalone customer service entry

---

## 2. Why Productization Matters Now

- Chen Kui trial needs a page that feels **sellable** and **trustworthy**
- First impression in 10 seconds: product vs lab
- Commercial risk: prospect sees "one tool among many" instead of "this is the product"
- Customer Entry must feel like a **formal insurance service entry point**

---

## 3. What This Sprint Will Strengthen

- **Trust / Hero**: Clear "what this page helps with" + "office will follow up"
- **Primary entry actions**: 获取报价, 保单变更, 报事故, 上传材料, 联系人工 — deliberate service entry points
- **Free input**: Secondary path, "not sure which to choose"
- **Visual structure**: Card boundaries, spacing, hierarchy, professional color direction
- **Page identity**: External, stable, trustworthy — not workbench subpage

---

## 4. What It Intentionally Will Not Do

- Full design system rewrite
- Giant navigation overhaul
- Backend business logic changes
- Advanced motion design
- New features (attachment, multi-turn, etc.)

---

*End of blueprint*
