# Sprint Blueprint — Frontend Redeploy + Founder Demo + Top Feedback Fixes

**Sprint:** Frontend Redeploy + Founder Demo + Top Feedback Fixes Sprint  
**Created:** 2026-03-14  
**Target budget:** 30–60 minutes

---

## Why this sprint matters

The product already has:
- Speed routing mainline
- Real customer pack mainline
- Case handoff mainline
- Trust boundaries
- Pilot/sellability polish

The next best move is **not more architecture**. It is:
- Ship the current frontend polish
- Run the strongest founder demo path
- Identify the biggest remaining hesitation points
- Fix only the highest-value ones

---

## What success looks like

1. **Frontend redeployed** — Latest polish live on production (Vercel)
2. **Founder demo run** — One realistic pass (R1, R2, SIM3 minimum; or SIM1, SIM2, SIM3)
3. **Top 1–3 issues identified** — Clear, actionable, prioritized
4. **Optional fixes** — Only if small, high-value, low-risk
5. **Final judgment** — Honest assessment of sellability and next step

---

## In scope

| Area | What |
|------|------|
| Control docs | Sprint Blueprint, Execution Outline, Acceptance/SLA |
| Pre-deploy check | Inspect polish, run `npm run build` |
| Frontend redeploy | `vercel --prod` from `ui/` |
| Post-deploy check | Build info bar, polish visibility |
| Founder demo | R1, R2, R3 or SIM1, SIM2, SIM3 |
| Top issues | Identify 1–3 highest-value issues |
| Optional fix loop | Wording, labeling, trust phrasing only |
| Iteration log | Every loop: what changed, better, not better, worth it |

## Out of scope

| Area | What |

| Broad polish | No random polish |

| Full backlog | Only top 1–3 issues |
