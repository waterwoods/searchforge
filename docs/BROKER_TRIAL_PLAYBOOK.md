# Broker Trial Playbook — 7 Days

**For:** Broker (e.g., Chen Kui) during a real trial week  
**Founder path:** [`TRIAL_ONE_PATH.md`](./TRIAL_ONE_PATH.md)  
**One-pager:** [`BROKER_ONE_PAGER.md`](./BROKER_ONE_PAGER.md)

---

## What you are trying

Paste customer messages → get a structured case with urgency, next move, collected/missing info, draft reply. **You review and send. Nothing auto-sends.**

---

## Day 0 (founder sets up)

Founder runs `bash scripts/trial_launch_check.sh` and sends you:

- Workbench URL
- This playbook + one-pager
- WeChat/email for questions

---

## Day 1 — Learn the product (30–45 min)

1. Open **/workbench/unified-intake**
2. Click **Load founder demo queue** — 13 sample cases load; cancellation opens first
3. Open **Simulation Assistant** — run these three in order:
   - **Cancellation risk** (3 turns) — urgency, same-day action
   - **Missing document** (3 turns) — verify receipt, follow-up
   - **Add-car quote (Chinese)** (3 turns) — Collected / Still needed chips
4. Watch for: **Case focus**, **Your next move**, **Collected**, **Still needed**, **Human confirmation recommended**
5. Paste **one real message** (or click **Need an example?**)
6. Edit draft → copy to WeChat (don't send from system — copy manually)

---

## Day 3 — Real office use

1. Paste **2–3 real customer messages** from your week
2. For each: note Case focus, Your next move, whether draft was usable
3. Try **Update with new customer message** on a case with follow-up
4. Note anything confusing — send screenshot to founder

---

## Success criteria

You can explain to a colleague:

1. What the product does in one sentence
2. Which scenario you'd use first Monday morning
3. Whether you'd trust the draft as a starting point

---

## Failure criteria (tell founder immediately)

- You can't tell what the system did with your message
- Output feels wrong often enough that you wouldn't open it again
- You expected WeChat sync / auto-send and feel misled

---

## Support escalation

| Situation | Do this |
|-----------|---------|
| Stuck on one case >15 min | Screenshot + Copy case snapshot → founder |
| Page won't load | Tell founder; use Simulation Assistant if they confirm |
| Draft language wrong | Edit before sending — note pattern for founder |
| Urgent case while system down | Handle manually; log for founder |

---

## What to ignore

- Simulation Assistant scenario IDs (SIM1, etc.) — use scenario names
- `/demo` page — optional lookup tool, not the main product
- Backend warming messages — retry or ask founder
- Technical status bars — founder handles infrastructure
